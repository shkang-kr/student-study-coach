# 학습 코치 (프로그램 v3.0.2 · 데이터 형식 v3)

성적표를 바탕으로 학습 변화를 보고, 목표와 보강 계획을 세우고, 학부모·교사 화면으로 공유하는 스마트폰용 앱이에요.
**앱(프로그램)은 모두가 같은 것을 쓰고, 데이터는 각자 따로 가집니다.** 이 폴더에는 누구의 데이터도 들어 있지 않아요.

## 이 폴더를 전달할 때

폴더 전체(또는 같이 있는 zip)를 그대로 복사해서 전달하면 돼요. 배포 방법(주소, 서버, 설치)은 받는 쪽에서 정해요.

```
index.html              프로그램 전체 (화면 · 분석 · 데이터 형식 검사 · 암호화가 이 파일 하나에 있어요)
manifest.webmanifest    스마트폰 홈 화면 설치 정보
sw.js                   오프라인용 파일 보관(프로그램 파일만, 데이터는 보관 안 함)
config.json             설정 (성적표 읽기 서버 연결, 기본은 연결 안 함)
icons/                  앱 아이콘
data/                   데이터 폴더 (프로그램과 같은 위치)
  index.json            앱이 자동으로 보여줄 데이터 목록
  template-empty.json   빈 양식 (0점 예시, 실제 데이터 아님)
schema/                 데이터 형식 문서
  data-format.md        항목별 형식 (프로그램의 SCHEMA에서 자동 생성)
  CHANGELOG.md          형식 변경 기록
skill/school-coach-reader/   Claude 앱용 읽기 전용 스킬 (아래 설명)
tools/check.mjs         올리기 전 점검 스크립트 (node 필요)
.gitignore              사용자 데이터 파일이 실수로 올라가지 않게 막는 목록
```

### 데이터를 공유하지 않는 원칙
- 전달하는 복사본의 `data/`에는 빈 양식만 있어야 해요. **실제 사용자의 데이터 파일(암호화 파일 포함)을 이 폴더에 넣은 채로 다시 복사하거나 공유하지 마세요.**
- 앱은 데이터를 브라우저에 저장하지 않아요. 사용자가 "암호화해서 받기"로 내려받은 파일을 자기 폰에 보관해요.

## 사용 흐름 (Claude 앱 + 학습 코치 앱)

1. 성적표(또는 시험지·답안지·정답지)의 **이름을 가리고** 다른 카메라 앱으로 사진을 찍어요.
2. 폰의 Claude 앱에 사진을 올리고 요청해요. `skill/school-coach-reader`를 설치해 두면 Claude가 정해진 형식(JSON)으로 결과를 줘요.
   - 성적표 → 점수·문항 오답 표기 (`reportCard`)
   - 시험지·답안지·정답지 → 문항별 판정과 보강 과제 (`examJudgement`)
   - 학교 이름 → 주요 학사 일정 (`schedule`)
3. 결과 JSON을 복사해서 학습 코치 앱의 **"AI 결과 가져오기"**에 붙여 넣어요. 앱이 형식과 개인정보를 검사하고, 성적표는 사진과 비교해 확인·검산한 뒤 데이터에 넣어요.
4. 사진과 Claude 대화를 지우고, 앱에서 **"암호화해서 받기"**로 데이터 파일을 보관해요. 다음에 쓸 때 그 파일을 불러와요.

AI는 **읽기만** 하고, 분석·화면·암호화는 모두 앱이 해요. 그래서 모든 사용자가 같은 화면과 같은 분석을 봐요.

## 스킬 설치 (Claude 앱)

`skill/school-coach-reader` 폴더(또는 함께 있는 `school-coach-reader.skill` 파일)를 Claude의 설정 → 기능(스킬)에서 올려요. 스킬을 쓸 수 없는 환경이라면 `SKILL.md` 안의 내용을 대화나 프로젝트 지침에 그대로 붙여 넣어도 돼요.
Claude 앱의 기능은 계정·요금제·기기마다 다를 수 있으니, 먼저 한 번 시험해 보세요.

## 개인정보 보호 설계

- 데이터는 화면 메모리에만 있어요. 브라우저 저장소·쿠키에 저장하지 않고, 창을 닫으면 사라져요.
- 앱이 읽는 곳은 같은 위치의 `data/`와 `config.json`뿐이에요. 다른 곳으로 가는 연결은 보안 정책(CSP, index.html 맨 위 meta)으로 막혀 있어요.
- 데이터 파일에는 **가명 코드와 별칭만** 들어가요(`S001`, `학생 A`, `A학교`). 실제 이름·학번·학교 이름, 전화번호·주민번호·이메일처럼 보이는 글, 형식에 없는 항목이 있으면 불러오기를 막아요. 사람 이름은 글자만으로는 완벽히 가려낼 수 없으니, 일정 이름 등에 이름이 섞였는지는 사용자가 한 번 확인해야 해요.
- 저장 파일은 비밀번호로 암호화할 수 있어요(AES-256-GCM, PBKDF2). 비밀번호는 앱 화면에서만 입력하고 Claude 대화에는 입력하지 마세요. 잃어버리면 복구할 수 없어요.
- 사진은 **Claude 서버로 전송돼요.** 이름을 가려서 올리고, 사용 후 사진과 대화를 삭제하며, 계정의 대화 보관·학습 사용 설정을 확인해 주세요. 미성년자 정보이므로 보호자 동의와 법적 검토는 별도로 필요해요.
- 학사 일정은 학교 이름을 Claude에게 한 번 알려 주어야 찾을 수 있어요. 저장되는 데이터에는 일정만 들어가고 학교 이름·홈페이지 주소는 들어가지 않아요. AI가 모은 일정은 "확인 필요"로 표시돼요.

## GitHub 등 공개 저장소에 올릴 때

올리기 전에 `node tools/check.mjs`를 실행해 모두 통과하는지 보세요(데이터 폴더 점검, 개인정보·로컬 경로 흔적, 외부 불러오기·저장소 사용, 버전 일치, 보안 정책 해시).
**index.html을 고쳤다면 `node tools/check.mjs --fix`로 보안 정책(CSP) 해시를 다시 맞추세요.** 안 맞추면 브라우저가 스크립트를 막아 앱이 멈춰요.

- 저장소가 공개면 코드·문서·스킬·데이터 형식을 누구나 볼 수 있어요. 비밀 값과 사용자 데이터는 이 폴더에 없어요.
- 올리는 사람의 GitHub 계정 이름이 주소와 커밋 기록에 남아요. 저장소 이름에 학교·파트너 이름을 쓰지 말고, 이메일은 GitHub의 noreply 주소를 쓰는 걸 권해요.
- 공개 여부와 사용 허락 범위(라이선스)는 올리기 전에 정해야 해요. 라이선스 파일이 없으면 보는 것은 가능하지만 다른 사람이 마음대로 쓸 수는 없어요.
- GitHub Pages는 응답 헤더를 바꿀 수 없어서 보안 정책을 meta 태그로 넣었어요. 이 때문에 다른 사이트가 이 앱을 자기 페이지 안에 끼워 넣는 것은 막지 못해요(앱은 저장하는 데이터가 없어 위험이 낮아요).
- 같은 계정의 `계정이름.github.io` 아래 저장소들은 같은 사이트 주소를 나눠 써요. 이 앱은 브라우저에 아무것도 저장하지 않지만, 믿을 수 없는 다른 페이지를 같은 계정에 함께 올리지는 마세요.
- 사용자 데이터 파일(암호화 파일 포함)은 저장소에 절대 올리지 마세요. `.gitignore`는 git으로 올릴 때만 막아 주고, 웹에서 끌어다 올릴 때는 막지 못해요.

## 스마트폰 설치 (받는 쪽이 정해요)

- 폴더를 HTTPS 주소의 정적 호스팅에 올리고 폰 브라우저로 열어 "홈 화면에 추가"를 하면 앱처럼 쓸 수 있어요.
- HTTPS가 아니거나 파일을 그냥 열면 오프라인 설치와 암호화는 쓸 수 없고, data 폴더 자동 찾기도 되지 않아요(파일을 직접 고르는 방법은 가능).
- 새 버전을 올리면 사용자 화면에 "새 버전이 있어요"가 떠요(`sw.js`의 버전 이름을 함께 바꿔야 해요).
- 스토어 앱으로 만들려면 이 폴더를 앱 껍데기(Capacitor 등)로 감싸는 별도 작업이 필요해요.

## 데이터 형식과 버전 관리

- 형식은 index.html의 `SCHEMA`가 정의해요. 검사·문서·빈 양식이 모두 여기서 나오고, 앱의 "데이터" 화면에서도 표와 변경 기록을 볼 수 있어요.
- 이전 버전 파일은 앱이 새 형식으로 바꿔서 불러와요(`MIGRATIONS`). 더 새로운 형식의 파일은 "프로그램을 업데이트하세요"라며 막아요.
- v2: 샘플 성적표(채점 현황) 4종을 분석해 확장했어요(학년·학기·종류, 과목 코드, 객관식·서술형·실기, 성적표 총점·합계·평균, 문항별 오답 표기).
- v3: 학사 일정, AI 결과 가져오기 약속, 암호화 파일을 추가했어요.

### 새 성적표 형식이 들어왔을 때
1. 이름·학번을 가린 새 성적표 샘플을 개발 담당(Claude)에게 전달해요.
2. 앱의 **데이터 → 항목 보고서 받기**로 받은 `schema-suggestion.json`을 함께 주면 어떤 항목이 형식에 없었는지 알 수 있어요(값은 들어 있지 않아요).
3. 개발 담당이 형식을 확장하고 **형식 버전과 프로그램 버전을 함께 올려요**: `SCHEMA` 수정 → `SCHEMA_HISTORY` 기록 → 필요하면 `MIGRATIONS` 추가 → 스킬과 문서 갱신 → `sw.js` 버전 변경.
4. 새 폴더를 같은 방식으로 전달해요. 스킬과 앱의 형식 버전이 같아야 해요.

## 알려진 한계

- 사진을 읽는 AI는 이 폴더에 들어 있지 않아요(Claude 앱 등 외부 도구를 사용). 읽기는 틀릴 수 있어서 앱이 검산하고 사용자가 확인하게 해요.
- 분석은 규칙 기반이에요. 성취기준 연결과 문항별 정답 데이터가 있으면 더 깊은 분석이 가능해요.
- 시험지 판정은 객관식 문항만 다뤄요.
- 학교 홈페이지 구조가 제각각이라 학사 일정 수집은 실패하거나 틀릴 수 있어요.
- 실제 폰(아이폰·안드로이드)과 Claude 앱 환경에서의 설치·동작은 아직 확인하지 못했어요. 전달 전에 한 번 시험해 보세요.
- 선택: `config.json`에 읽기 서버를 연결해 성적표 자동 읽기를 쓸 수 있어요(`{"parser":{"mode":"remote","endpoint":"https://…"}}`). 이때 사진이 그 서버로 전송되므로 CSP의 `connect-src`에 주소를 추가하고 동의를 받아야 해요.
